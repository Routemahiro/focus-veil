# Feature Design TODO

## 定義

このTODOは、今後の追加機能を実装する前に、設計として決め切る項目を管理するためのものです。対象は、現在採用候補として残した `Focus Profiles`、`Ambient Progress`、`Gentle Breaks` です。

Return Markerは保留です。今後扱う場合は、単なる位置マーカーではなく、最後の作業文脈を復元する `Return Context` のような別機能として再設計します。

## 要点

- まず `Focus Profiles` と `Ambient Progress` を設計完了まで持っていく。
- `Gentle Breaks` は固定タイマーを残したまま、通知タイミング調整として設計する。
- 実装前に、設定スキーマ、操作UI、トレイ表示、複数ディスプレイ時の挙動、smoke検証観点を決める。
- 研究根拠は `docs/research-connections.md` に分離し、このTODOでは設計作業だけを追跡する。

## 比較

| 項目 | 現在の判断 | 設計完了条件 |
| --- | --- | --- |
| Focus Profiles | 採用 | 各プロファイルのパラメータ、UI、保存形式、手動調整との関係が決まっている |
| Ambient Progress | 採用 | 表示位置、見た目、強度段階、タイマーUIとの関係が決まっている |
| Gentle Breaks | 条件付き採用 | 固定タイマーとの関係、猶予条件、最大延長、通知表現が決まっている |
| Return Marker | 保留 | 作業文脈復元として再定義するまで着手しない |
| 通知制御、音、ブロッカー | 今回は見送り | Focus Veilの中核と離れるため、別フェーズで判断する |

## 具体例

### 1. Focus Profiles

- [ ] Profile名を確定する: `Code`、`Read`、`Write`、`Scan`。
- [ ] 各Profileの初期値を決める。
  - [ ] `veilAlpha`
  - [ ] `spotlightRadius`
  - [ ] `spotlightSoftness`
  - [ ] 追従スムージング
  - [ ] motion highlightの強さ
  - [ ] Ambient Progressの強さ
- [ ] Read用に縦長スポットライトを入れるか決める。
- [ ] Scan用にスポットライト感を弱める描画分岐を入れるか決める。
- [ ] ユーザーが手動でスライダー調整したとき、Profileを上書きするのか、`Custom` 扱いにするのか決める。
- [ ] 操作モード内のUI形式を決める。
  - [ ] セグメントコントロール
  - [ ] ドロップダウン
  - [ ] トレイメニュー
- [ ] 複数ディスプレイ時にProfileを全ディスプレイ同期にするか、ディスプレイ別にするか決める。
- [ ] 設定保存のスキーマを決める。
- [ ] README上の説明文を決める。

### 2. Ambient Progress

- [ ] 表示形式を決める。
  - [ ] 画面端ライン
  - [ ] コーナーリング
  - [ ] 現在の右下タイマーとの併用
- [ ] 表示位置を決める。
  - [ ] 下端
  - [ ] 上端
  - [ ] 右端
  - [ ] Primary displayのみ
  - [ ] 全display
- [ ] 強度段階を決める: `off`、`subtle`、`visible`。
- [ ] Focus中とBreak中の色を決める。
- [ ] 終了直前パルスの有無と開始タイミングを決める。
- [ ] タイマー数字を通常時も残すか、Ambient Progress有効時は弱めるか決める。
- [ ] 操作モード内で残り時間をどの程度表示するか決める。
- [ ] smokeスクリーンショットで進捗が非ブランクかつ主張しすぎないことを確認する観点を定義する。

### 3. Gentle Breaks

- [ ] 固定タイマーを基本にする前提を仕様へ明記する。
- [ ] タイマー終了時に即休憩へ入るのか、提案状態を挟むのか決める。
- [ ] 直近入力の判定条件を決める。
  - [ ] キー入力
  - [ ] マウス移動
  - [ ] クリック
  - [ ] スクロール
- [ ] 猶予時間を決める。例: 15秒、30秒、60秒。
- [ ] 最大延長時間を決める。例: 3分、5分。
- [ ] 延長中のAmbient Progress表現を決める。
- [ ] 休憩提案をユーザーが無視した場合の挙動を決める。
- [ ] 強制ロックや中央モーダルは採用しないことを仕様へ明記する。
- [ ] 効果表現を決める。
  - [ ] OK: 疲労を抑える
  - [ ] OK: 休憩への移行を邪魔しにくくする
  - [ ] NG: 集中力が必ず上がる

### 4. Cross-Feature Decisions

- [ ] ProfileごとにAmbient Progressの強さを変えるか決める。
- [ ] ProfileごとにGentle Breaksの猶予挙動を変えるか決める。
- [ ] `Motion highlight` と `Focus Profiles` の関係を決める。
- [ ] トレイメニューに出す項目を最小化する。
- [ ] 操作モードUIでテキストがはみ出さない幅を決める。
- [ ] 設定ファイルの後方互換性を決める。
- [ ] smoke用の短時間タイマーで各機能を検証できるようにする。
- [ ] 長時間手動確認の観点を決める。
